Objetivo: Documentar o mapeamento das fontes, a definição do schema unificado e as regras de normalização dos dados que alimentam o Dashboard PRPGI.

4. Regras de Normalização

4.1 Extração de ID do Servidor (SUAP CNPq)

O campo Servidor nas planilhas Excel contém uma string complexa no formato:

<Vínculo: Nome Completo (1234567) (Servidor)>

Para coautorias, o campo pode conter múltiplos servidores separados por vírgula.

Regra: extrair todos os números de 7+ dígitos com regex (\d{7,}) e criar um registro individual para cada servidor.

4.2 Desduplicação

Cada registro de produção recebe uma dedupKey gerada a partir da normalização do título:

  • Remoção de acentos
  • Remoção de caracteres especiais
  • Lowercase
  • Remoção de espaços extras

No frontend, quando o toggle "Desduplicar" está ativo, registros com mesma dedupKey e mesmo ano são contados uma única vez.

4.3 Normalização de Unidade (DGP)

  • Se Unidade vazio ou começando com "Instituto Federal da Bahia" / "Instituto Federal de Educação", assume "Salvador"
  • O nome do campus é extraído do padrão "IFBA - Campus [Cidade]"

4.4 Filtro IFBA vs IFBaiano (crítico)

A Instituição deve conter "IFBA". Registros de "IFBaiano" (instituição distinta) são descartados.

4.5 Normalização de Curso (Pós-Graduação)

O campo curso tem formato: 64 - MESTRADO PROFISSIONAL EM ... (Salvador)

Regra: remover prefixo numérico e campus entre parênteses ao final. Original em curso_original, simplificado em curso.

4.6 Extração de Ano/Semestre (Pós-Graduação)

O campo ano/período letivo tem formato YYYY.S (ex: 2016.2).

  • ano = parte antes do ponto (inteiro)
  • semestre = parte depois do ponto (1 ou 2)

4.7 Inferência de Categoria (Pós-Graduação)

A categoria é inferida nesta ordem:

  1. Do campo modalidade ("Mestrado", "Doutorado")
  2. Do nome do curso (contém "DOUTORADO", "MESTRADO", "ESPECIALIZACAO")
  3. Padrão: "Outro"

5. Pipeline de Dados

Excel (25 campi) ─┐
                  ├──> scripts/build.js ──> data.json (~27 MB) ──> Dashboard
CSV DGP ──────────┘
CSV Pós-Graduação ─┘
  • scripts/build.js (Node.js + SheetJS) varre dados/, processa cada fonte, aplica normalizações e gera o JSON consolidado
  • O frontend carrega data.json via fetch único na inicialização
  • Toda lógica de filtro, agregação e desduplicação é executada no cliente (client-side BI)
